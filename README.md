## 软银VPS是什么，哪些人买了不亏

软银线路就是日本软银集团的国际骨干网，在搬瓦工的产品体系里代号是BBTEC，机房编号JPOS_1，位置在大阪的Equinix数据中心。这条线经海底光缆连回中国大陆，国内侧的表现以联通方向最好。

延迟差多少，看数字最直接。搬瓦工公开测评里的说法是，大阪软银机房到国内联通通常只有60~80ms；同期洛杉矶CN2 GIA对联通的平均延迟在150~200ms。这个差距落到实际使用上，是网页打开更快、视频缓冲更少、SSH敲命令回显不卡。VMISS东京TRI的第三方测评是另一个测点，联通方向平均延迟60ms上下，晚高峰也基本不飘。两个数字来自不同商家、不同测试点，别当成一个“软银标准延迟”记。

适合买的人就三类：家里或公司拉的是联通宽带；做站、做服务，访问者以联通用户为主；业务本身在日本，需要一个东京或大阪节点。第三类其实跟软银关系不大，日本机房物理距离近，换哪条线延迟都低。

不适合的同样明确。电信重度用户，同样预算去看CN2 GIA更对路；需要IPv6的、需要1Gbps以上带宽的，便宜档的软银方案基本给不了。

还有一件事得先说清楚：商家页面写着“软银”，不等于你买到的那台机器三网都走软银。评测站点VPSSpy在自己软银目录页上写得很直白，他们列出的SoftBank标签来自官方套餐名和既有分类规则，不是实测结果，该站没有独立测量过路由、延迟和吞吐。标签只能当筛选入口用，下单前要看路由说明或者商家的测试IP。

## 同样是“软银”，为什么体验能差一大截

差别在软银覆盖了哪一段。市面上常见两种结构：一种是全程软银，去程回程都走SoftBank；另一种只在去程借一段软银，回程交给别的高端线路。

VMISS东京TRI是后一种里比较好懂的样本。它的去程让电信和联通都走软银进日本，回程分开处理：电信走CTG/CN2，联通走AS10099加AS4837，移动从东京CMI直连回国。这么做的道理是去程拿软银的低延迟，回程各走各家最顺的路。有些标着“软银”的方案，回程也走软银的普通BGP，晚高峰体验会差一截。

还有一种更省事的做法：只对联通走软银，电信照样绕路。宣传页上照样写“软银线路”，你电信宽带买回去，测出来跟普通日本机房没区别。

判断办法不复杂。翻商家的路由说明，看它写的是“三网软银”还是“联通软银”，回程走什么；再看有没有公开的测试IP，自己ping一下、traceroute一下，比看宣传词靠谱得多。

## 短板：这几种情况别买软银

软银对电信和移动不友好，这不是个别商家的问题，是线路本身的偏向。多家测评的口径一致：电信和移动方向丢包率偏高，高峰期速度不稳。你是电信宽带、又只服务电信用户，买软银等于花钱买了个不适合自己的方向。

标签不等于实测，这一点前面说过，值得再强调一次。VPSSpy在目录页声明自己的标签不是实测，还提醒价格和库存列表用的是同一个快照、徽章独立刷新，“未知库存、检查失败和售罄是三种不同状态”。看到“有货”不等于下单就能交付，价格快照也可能滞后。

便宜档的带宽普遍不大。VMISS东京TRI最高300Mbps，GreenCloud的入门档、六六云的中低档也多在100M到500Mbps这个区间。要1Gbps就得换产品线，这不是加钱能解决的事，是产品定位不同。

非原生IP是另一个常见坑。搬瓦工的日本软银明确不是日本原生IP，六六云把原生IP单列成一条路线，本身就说明软银线路和原生IP是两件事。

最后是外部环境。六六云官网公告里专门写过“墙高峰”，说近期不少用户遇到服务器ping得通、但SSH或业务端口连不上，主要表现为TCP连接在中国大路段受限。这种事跟商家选哪条线无关，买任何日本VPS都该有这个预期。官方给出的应对是关机保IP，或者把传输方式做得更隐蔽些。

### 软银VPS电信能用吗

能用，但拿不到联通那种体验。电信方向延迟更高、高峰期丢包更明显。电信重度用户优先看CN2 GIA。

### 软银和CN2 GIA哪个好

看你的运营商。联通用户走软银更快，60~80ms这个量级是CN2 GIA给不了的；电信用户走CN2 GIA更稳。拿不准就买那种可以自由切换机房的套餐，两个都测。

### 为什么同样标着软银，延迟差很多

三种可能：只对联通走软银，你的运营商不在优化范围；去程走软银、回程走普通BGP；或者机房位置不同。买前看路由说明和测试IP。

### 日本软银能解锁Netflix吗

不一定。软银线路和IP是不是日本原生是两回事，搬瓦工的日本软银就明确不是原生IP。要解锁日区内容，得按IP属性挑，别按线路名挑。
